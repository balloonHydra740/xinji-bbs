# 星铃 BBS ☁️

一个可直接部署到 Cloudflare Workers + D1 的现代文字 BBS。

## 功能
- 现代响应式 UI，弹性非线性动画（并遵循系统的「减少动态效果」偏好）
- **6 套配色方案 + 深/浅/跟随系统**：设置面板里随手切换，只存在本机（`localStorage`），
  换设备不会跟着走。主题色贯穿全站（主按钮、选中的板块条目/档位、卡片标题的小竖条、
  统计数字、进度条、各处悬停描边），换配色时整页观感都会变。
  所有颜色都走 `--p-*` 变量，加新配色只要往 `style.css` 里抄一块、往 `app.js` 的
  `PALETTES` 里加一行 —— 两边是否一致由测试盯着（见下）
- **管理中心带用户搜索**：按用户名 / 角色 / 封禁状态过滤，本地即时出结果
  （接口一次给 200 条），只重画列表那一块，不会把输入框和光标冲掉
- **附件入口只有一个**：Markdown 工具栏里的「＋ 图片/视频/音频」。
  它是 **`<label for>`** 而不是靠 JS 调 `input.click()` —— label 由浏览器原生触发，
  各内核 / 移动端都稳；JS 调 `.click()` 在部分移动浏览器里会被判成「非用户手势」
  而静默失效（点了完全没反应，也看不到报错）。
  标签必须写全三个类型，只写「图片」会让人以为音视频传不了。
  上传时输入框下面出现进度条（主题色渐变 + 一道来回扫的高光）、
  「正在上传 2/3 · 46%」的文案和一颗「取消」。字节发完之后文案会切成
  「正在保存到存储…」—— 那一段服务端在写网盘、没有任何进度事件，
  不换文案的话看着就像卡死
- **上传上限会自动夹到平台的墙**：Workers 的请求体硬上限是 100 MB
  （超过它请求**连 Worker 都到不了**，客户端只会一直等），所以
  `uploadLimitBytes()` 会把库里的值夹到 100 MB，管理面板保存超限值时也会提示实际生效多少。
  `/api/status` 会把生效上限下发给前端，选完文件立刻本地判大小，不必发上去再被拒
- **不易展示内容（隐藏限制帖）**：发帖 / 回复 / 编辑时可以勾选「不易展示」（剧透、
  公共场合不宜）。这类内容对**开了模糊的人**会先盖一层遮罩 + 模糊，
  必须把滑块拖到底才显示完整内容（半路松手会弹回，键盘按回车也行）；
  列表里则只做轻度模糊并打上「不易展示」角标，点进去再确认。
  看不看得到由**看的人**决定：账户设置 → 内容限制里那颗开关关掉后，
  这类内容就跟普通帖子一样直接显示（默认开启，游客也按开启处理）。
  作者本人随时能改自己的标记，管理员与子管理员可以替别人补标或撤标
  （走 `moderate` 的 `sensitive` 动作，属于内容治理白名单）。
  只翻标记不会写进编辑痕迹 —— 那张表记的是正文改动
- **点赞 / 转帖 / 引用（X 式互动）**：三件事各有各的位置，别混着理解 ——
  - **点赞**：一人一次、可撤销，唯一的后台拦截是那张 `(target_type,target_id,user_id)` 唯一索引
    （并发点两下也只有一行生效）。心形默认只描边，赞过才填色；点下去会弹一下 + 扩散一圈光环，
    数字往上滑一下 —— 数字从 3 变 4 这种变化太安静，没有反馈很多人会怀疑自己到底点没点上。
    主题和回复都能赞；
  - **转帖**：引用别人的内容**新发一条主题**（就是引用转帖），原帖计一次「转帖」。
    标题留空会自动补成「转帖：原标题」，正文也可以留空（只挂一张引用卡 = 直接转）；
  - **引用**：在**回复**里挂一张引用卡。它属于楼内讨论、**不**计入转帖数 ——
    回复引一句原帖不该让「转帖 3」这个数字变得讲不清。
  - 「评论和帖子都能被新发帖或评论引用」是同一套机制：`quote_ref` 记 `'thread:12'` / `'post:34'`，
    数据库里**刻意不加外键** —— 原内容被删之后引用卡还要照常显示（只多一句「原内容已删除」，
    点了也不会撞上死链）。所以引用卡一律照**服务端生成的快照**渲染（作者 + 标题 + 摘要 + 时间），
    前端传什么都改不了别人看到的内容；
  - **转帖时能勾「不易展示」**，而且引用卡会跟着收内容：原内容带限制标记时，
    转帖弹窗默认替你把勾打上，引用卡上的标题与摘要一并换成「内容已隐藏」。
    引用不该成为绕开限制的后门。
  - 删主题 / 删回复 / 删号 / 存储清除都会顺手清掉挂在内容上的赞（`likes.target_id` 不是外键，
    不自己收尾就会留下永远读不到的行）
- **投票**：帖主和评论者都能在**自己的**主题 / 回复里挂一个投票 ——
  - 一条内容最多一个投票（`polls(target_type,target_id)` 唯一索引兜底，并发提交也不会冒出两张卡）；
    发帖 / 回复时就能带上，也可以事后在内容下面点「＋ 投票」补一个；
  - 问题一句话 + 2~10 个选项，可以勾「允许多选」。**每个账号只能投一次**：
    兜底的是 `poll_ballots(poll_id,user_id)` 唯一索引 —— 并发点两下、网络重试发两次都只算一次。
    票拆两层存（选票 = 一人一次，勾选项 = 投了哪几项）就是为了让多选和「一人一次」同时成立；
  - **没投票前不显示票数**：「大家都选 A」会带着人走，那就不叫投票了；
    投过之后（以及没登录的游客）同一个位置换成结果条 —— 人数、每项票数与百分比，
    自己投的那一项带 ✓ 和高亮。投票完只重画**这一张卡**，不整屏重画（滚动位置会丢）；
  - 每人只有一票、投完不能改；已经有人投过票之后作者也不能改选项或移除投票
    （悄悄把别人的票换一组选项比不给改更糟），需要改就找站主；
  - 列表里只给一句摘要（「今晚吃什么？· 3 人参与 · 单选 · 去投票 →」），
    选项和结果点进详情再看 —— 在列表里铺开一排选项既占地方，也容易让人以为能直接投；
  - 内容标了「不易展示」时，投票跟着正文一起被遮住：只遮正文等于限制标记形同虚设；
  - 删内容时投票跟着进回收站快照（`payload._poll`，含每个人的票），恢复时按**原 id** 写回 ——
    否则「后悔药」捞回来的帖子会少掉投票和票数
- **回收站（后悔药）**：删除不再是「一按就没」——
  - 删主题 / 删回复 / 删号都先把**整行快照**写进 `trash` 再从活跃表删掉；
    恢复时按**原 id** 写回，所以别人的引用卡（`quote_ref`）不会指向空气；
  - 删主题是「整楼收走」：主题 + 它下面所有人的回复各存一条记录（靠 `parent_id` 归拢），
    恢复时一起放回来。**不**打包成一条 JSON —— 热门长帖能顶破 D1 单行 2 MB 的上限；
  - **自己删的自己能捞回来**：删除之后的提示条上直接挂一颗「撤销」（5 秒内点它就行），
    也可以在「头像菜单 → 回收站」里慢慢找。被管理员移除的内容只有站主能恢复 ——
    治理动作放开让作者一键推翻就没意义了。回收站里会明确标出「自己删的 / 管理员移除」；
  - **删号也能救回来**：整包（账号行含密码哈希 + 全部主题回复 + 附件清单）一起收着，
    站主点一下就能把账号和内容原样放回来（用户名被占用了就自动加 `-restored` 后缀）；
  - 附件是**只存元数据、不删远端**的 —— 远端一清，恢复回来的就是一堆破图。
    真要腾空间，在回收站里点「彻底删除」，那一步才连远端一起清；
  - 顺带：清理孤儿附件时会把回收站里的正文也算作「有人引用」，
    不然删帖 24 小时后再恢复，图就没了
- **内容保护（站主专属）**：站主可以把一条主题或回复「保护」起来 ——
  之后**除了站主谁都动不了它**：原作者不能改也不能删（所有权临时交给站主），
  子管理员的置顶 / 锁定 / 标记 / 删除也一并被挡（白名单不是免死金牌）。
  取消保护就原样还给作者。被保护的内容会挂上「已保护」角标，
  详情页还有一句「这条内容已由站主保护：原作者不再能修改或删除它」。
  前端在受保护内容上**不渲染**那排按钮 —— 免得点了才吃一个 403
- **胁迫密码**：遇到「有人逼着你解锁手机」时用的备选密码。
  - 在「账户设置 → 胁迫密码」里设一个（要验当前密码，不能和登录密码相同，至少 8 位），
    它和登录密码是两个独立哈希，改登录密码不会把它冲掉；
  - 用它登录 → 账号立刻进入**保护状态**：**内容一条都不删**、账号**从此刻起谁也用不了**
    （真密码、胁迫密码一律登不进去），只有站主能手动解除；
  - 触发那一刻**不下发任何会话**，连正在其它设备上的登录态也一并作废；
    返回给前端的那段「账号已进入保护状态」只是把状态说清楚，不是登录成功；
  - 之后无论输真密码还是胁迫密码，表现完全一致 —— 屏幕对面的人看不出哪一串才是「真的」；
  - 站主可以在管理中心手动把某个账号置入保护状态或解除（解除后胁迫密码依然保留，下次还能用）；
  - **管理员不给设置**：这个功能的出口是「只有站主能恢复」，管理员一触发就等于把自己锁在门外
    （真遇到胁迫，管理员直接在设置里改密码即可，改完其它设备立刻掉线）
- **Markdown 工具栏**：发帖 / 回复 / 编辑都带按钮（加粗、斜体、删除线、标题、引用、
  代码、代码块、链接、列表、编号、分隔线、图片/视频/音频），**按钮上写中文**且标签本身演示效果
  （加粗是粗体、斜体是斜体、删除线带删除线），悬停再补一句语法示例 ——
  纯符号（B / I / S / `</>`）只有写惯 Markdown 的人认得出，对新手等于没有标签。
  旁边还有「预览」，渲染结果和发表后完全一致
- **动效克制但有**：列表 / 导航条目 / 楼层按序号错开进场，卡片悬停微抬 + 主题色描边，
  弹窗淡入上浮（`::backdrop` 一起淡入）、提示条滑入、回复框展开时淡入、
  上传进度条有扫光、点赞时心形弹跳 + 光环扩散 + 数字上滑 ——
  全部遵循系统的「减少动态效果」偏好（弹窗的 `::backdrop` 不匹配 `*`，
  得单独点名关掉，否则窗口不动、遮罩还在自己淡入）
- **小屏有两种形态：窄，和矮**。以前「手机排版」一律按宽度判断，于是 844×390 的手机横屏被
  当成桌面：hero 照占 250px、详情页也收不起 hero 与板块栏，首屏只剩一条缝。
  现在宽度窄 **或** 高度矮都算小屏（`@media(max-width:900px),(max-height:600px)`），
  横屏再加上把 hero 压成一行（标题 + 统计同行，pill 收掉），首屏还给内容。
  这一坑由 `tests/viewport-check.cjs` 用 7 种比例真渲染盯着
- **平板与横屏的内容不再拉满整屏**：桌面那档的 `--maxw`（1060）在 720-1080 这段不生效，
  于是 768 宽的卡片一行能塞 40+ 个汉字，视线横扫很累（中文 30-40 字一行最好读）。
  新增两档：720-900 → 680px、900-1080 → 840px，都居中
- **手机端优先**：
  - 顶栏收成「左上角菜单 + ＋发帖 + 头像菜单」，弹窗变底部抽屉（带抓手），安全区留白
  - **操作按钮的尺寸与排版专门为拇指调过**：`.mini` / `.act` 放大到 34px（30px 在触屏上
    点「赞」和「转帖」经常串台）；一排操作按钮**不拉伸** —— 按钮多到折行时，
    `flex:1` 会让落单的那颗变成横贯整行的宽按钮，又丑又容易误点
  - **抽屉里的主提交按钮吸底**：填完表单不用再滚一段去找「发布」。
    注意 `position:sticky` 的偏移基准是**内容盒**，只写 `bottom:0` 的话正文会从按钮下面
    漏出半截字；要额外铺一条实色 `::after` 盖住那段（换成负 `bottom` 不行：iOS 安全区一变大
    按钮就被弹窗底边裁掉）。这条由 `snapshot` 的 `elementFromPoint` 断言盯着
  - **编辑器工具栏在手机上一行横滑**：14 个按钮堆起来要占三行、近半个抽屉，
    行尾那颗的宽度还随字数乱跳
  - **管理行改成上下两段**（先「头像 + 名字 + 标签」，按钮组另起一行右对齐）：
    左右并排时按钮组吃掉 200 多像素，左边的标签被挤成一行一个字，看着像乱码
  - 首页 hero 只留标题，统计数字挪到 pill 同一行（原来它独占一行，首屏白吃 110px）
  - 板块筛选按钮宽度贴着文字，不再拉满整行（拉满之后跟搜索框长得一模一样，看不出是按钮）
  - **iOS 上真的能用**：锁背景滚动走 `position:fixed`（Safari 不吃 `overflow:hidden` 那套），
    浮层滚动区带 `overscroll-behavior`，`backdrop-filter` / `appearance` 都带 `-webkit-` 前缀，
    `color-mix` 的边框与阴影都有纯色退路。这些由 `tests/safari-check.cjs` 盯着
  - 看帖子 / 主页 / 管理中心时自动收起首页的 hero 与板块栏，正文立刻出现
  - 首页 hero 只留标题（那句介绍在手机上纯占位）
  - **回复框默认折叠成一行**「＋ 写下回复……」，点一下或点任意一楼的「回复」才展开 ——
    展开后是 textarea + 工具栏 + 附件 + 按钮，在手机上要占掉大半个屏幕
  - 管理中心每行的按钮组等宽（104px）右对齐，放不下才整体换行，不会跟着用户名长短参差
- **附件上传（可选，站主开关）**：二进制本体存外部存储（WebDAV 或 Cloudflare R2），
  D1 只留索引；**类型一律按魔法字节判定**，不信浏览器上报的 Content-Type
- **附件读取（`GET /api/files/:id`）踩过的三个坑**，都跟「有的附件就是打不开」有关：
  - **`Content-Type` 要有兜底链**：入库时按魔法字节判的 mime → 存储服务给的 → 按存储路径
    的扩展名反查。WebDAV 服务器（尤其网盘）经常对图片也回 `application/octet-stream`，
    而全站带 `X-Content-Type-Options: nosniff` —— 于是浏览器**拒绝**把它当图片渲染。
    偏偏最早那批附件没存下 mime，表现就是「有的能看、有的打不开」
  - **必须给 `Content-Length`**：`<video>` / `<audio>` 靠它算时长和可拖拽范围，
    缺了它 iOS Safari 会直接不播、进度条也点不动
  - **存储回了 206 却没有 `Content-Range`**：拿它当全量用会得到一段「残缺文件」
    （视频放一半断掉、图片只显示上半截）。这时回退一次不带 `Range` 的请求 ——
    宁可不能拖拽，也不能把半段内容当完整文件交出去
  - 前端也不再只给一块红虚线框：图片加载失败**先自动重试一次**（远端限速/瞬断很常见），
    再失败才提示，而且**点一下能重试**（带时间戳绕开缓存）；HEIC 这类浏览器普遍不支持的格式
    会直接把原因写在提示里。音视频**不自动重试**（文件大，重试太贵），改成插一条可点的提示
- 用户注册 / 登录 / 退出
- 第一次打开自动初始化管理员
- 主题 + 回复
- **账户自助**：修改用户名、修改密码（需验证当前密码，改后其它设备会话失效）
- **注销账号**：输入用户名确认后永久删除账号及其全部主题、回复
- **两步验证 2FA**：TOTP（RFC 6238），兼容 Google Authenticator / 1Password / 微软 Authenticator
- **删除自己的内容**：用户可删除自己的主题与回复
- **三级权限**：
  - 普通用户 —— 只能删自己的内容
  - **子管理员**（moderator）—— 内容治理：置顶、锁定、删帖、删回复
  - 管理员（admin）—— 全权：另加封禁/解封、**删号**、重置密码、**关闭他人 2FA**、任命/撤销子管理员
- 密码使用 PBKDF2-SHA-256 派生，不保存明文密码
- Cookie Session（HttpOnly / Secure / SameSite=Lax）
- D1 数据库 + Workers Static Assets
- **零第三方外链**：二维码库已本地化，不依赖任何 CDN
- **讨论板块**：所有登录用户都能建板块，只有管理员能删；管理员/子管理员可以把别人的帖子挪到别的板块
- **左上角导航菜单**：板块不再横排成一排胶囊 —— 板块一多就换两三行，首屏先被一排按钮占掉。
  现在点左上角的菜单按钮滑出抽屉：板块按行排（名字吃满剩余宽度、计数固定右对齐、
  选中项带主题色标记），深浅三档也从顶栏收进来（原来那颗按钮只能「盲翻」，
  看不出当前是哪一档）。列表区只留一颗「板块 ▾」按钮显示当前筛选 ——
  没有它，用户看不出列表正被筛过，只会以为帖子少了。抽屉用 `transform` 进出场、
  条目按序号错开淡入，点遮罩 / 按 Esc 都能收起
- **图片等比缩放**：任何比例（含正方形）在任何屏幕都只缩小不拉伸，列表里另排整齐的缩略图
- **音频附件**：MP3 / M4A / AAC / WAV / Ogg / Opus / FLAC / WebM 音频 / AIFF / AMR / MIDI。
  详情页渲染成原生播放器，列表预览显示为「🎵 音频」占位。
  纯音频的 WebM 与 M4A 会靠轨道信息跟同名视频区分开，不会被塞进 `<video>` 变成一块黑屏
- **零跨站请求**：连 Cloudflare 自带的 NEL 上报也关掉了（见下），页面只和自己的域名通信，
  广告拦截器不会再报「拦截了 1 个广告或追踪器」

## 部署
需要 Node.js 和 Wrangler。

### 1. 安装依赖
```bash
npm install
```

### 2. 登录 Cloudflare
```bash
npx wrangler login
```

### 3. 创建 D1
```bash
npx wrangler d1 create xinji-bbs
```
把命令输出的 `database_id` 填进 `wrangler.jsonc`，替换 `REPLACE_WITH_D1_DATABASE_ID`。

### 4. 创建数据库表
```bash
npx wrangler d1 migrations apply xinji-bbs --remote
```

### 5. 本地测试
```bash
npx wrangler dev
```

### 6. 部署
```bash
npx wrangler deploy
```

部署成功后 Wrangler 会给出 `*.workers.dev` 地址。

## 从旧版本升级（无损）
已有站点升级不会丢失任何用户数据 —— 数据与代码分离，数据库变更只做「加法」。

> **容错设计**：Worker 内置表结构自检，部署后首次请求会自动补齐缺失的列与表（幂等，可安全重复执行）。
> 因此即便一时忘记执行下面的迁移命令，站点也不会崩溃报错；仍然建议按步骤执行，让结构变更可追溯。

```bash
# 1. 先备份（强烈建议）
npx wrangler d1 export xinji-bbs --remote --output backup.sql

# 2. 应用新增迁移（例如 0009：点赞与转帖）
npx wrangler d1 migrations apply xinji-bbs --remote

# 3. 重新部署代码
npx wrangler deploy
```

说明：
- D1 会记录已执行过的迁移，重复执行是安全的，只会跑还没应用过的新文件。
- **不要**回头修改已应用过的迁移文件；后续变更一律新建 `0004_xxx.sql` 这样的新文件。
- 新增列都带默认值，老数据会自动补齐，已有功能不受影响。
- 新增的 2FA 默认关闭，老用户照常登录，可在「设置」中自行开启。
- 老用户默认都是「普通用户」，子管理员需要由管理员手动任命。
- **0009（点赞 / 转帖）同样是纯加法**：只新建 `likes` 表、给 `threads` / `posts`
  各加两个可空列（`quote_ref` / `quote_snapshot`）。老内容一行不动，
  没有引用的内容 `quote_ref` 为 `NULL`，前端按「不是转帖」处理；点赞数从 0 开始。
  由 `ensureReactions()` 兜底补齐。
- **0010（回收站 / 内容保护 / 胁迫密码）同样是纯加法**：只新建 `trash` 表，
  给 `threads` / `posts` 各加两个可空列（`protected` / `protected_at`），
  给 `users` 加四列（`duress_hash` / `duress_state` / `duress_at` / `duress_by`）。
  老内容一行不动：`protected` 默认 0（和以前一样），没人设过胁迫密码，回收站是空的。
  同样由 `ensureModeration()` 在部署后首次请求时兜底补齐（顺序：widen → boards →
  features → sensitive → reactions → moderation，**每一步都必须在 widen 之后**）。
  ⚠️ 从这一版起**删号不再立刻清远端附件** —— 要腾空间请在回收站里点「彻底删除」。
- **0011（投票）同样是纯加法**：只新建三张表（`polls` / `poll_options` / `poll_ballots` /
  `poll_votes`），不改任何老表。老内容一行不动 —— 没有投票的内容就是「没有投票」，
  前端不渲染那张卡。由 `ensurePolls()` 在部署后首次请求时兜底补齐，
  顺序排在最后（`widen → … → moderation → polls`）：`poll_ballots` 引用了 `users`，
  提前建起来会让 `widenRoleConstraint` 的 `DROP TABLE users` 被外键拒绝，
  整批回滚、角色约束就永远放宽不了（`likes` 踩过同一个坑）。
  ⚠️ 「一人一次」的兜底是 `poll_ballots(poll_id,user_id)` 唯一索引，**别把它改成非唯一**：
  票拆成「选票 + 勾选项」两层，就是为了让多选和一人一次同时成立
  （把 `user_id` 直接放在勾选项上会让一个账号只能有一行，多选直接失效）。

### 0003 迁移（子管理员角色）为什么是「空操作」
SQLite 不支持修改已有的 `CHECK` 约束（`role` 原来是 `IN ('user','admin')`），
只能重建表。而重建被外键引用的表需要临时关闭外键——D1 的 `migrations apply`
会把整份 SQL 当作一次批处理执行，事务内 `PRAGMA foreign_keys=OFF` 是空操作，
做不到。因此：

- `0003_moderator_role.sql` 只做数据层面的安全兜底（确认表在、把历史脏角色归一）；
- 真正的表结构升级由 `src/index.js` 的 `ensureSchema()` 在部署后**首次请求时**完成：
  它会读 `sqlite_master` 判断 `users` 的 `role` 约束是否已含 `moderator`，
  没有就重建表（按原名保留全部列与行，先关外键再改名，最后补回唯一索引）。
- 这一步是幂等的，重复请求只会在第一次真正执行；失败也不会中断业务请求。

**不需要手工干预**，按上面的三步走完即可。老库里的用户、主题、回复、
会话、2FA 密钥都会原样保留。

## 「广告拦截器提示拦截了一个追踪器」是怎么回事

用无头浏览器抓过一次真实网络日志，根因不是页面里的广告，而是 **Cloudflare 自动加的
NEL（Network Error Logging）**：

- Cloudflare 会给响应挂上 `Nel` / `Report-To` 头，指向 `https://a.nel.cloudflare.com/report/...`。
- 浏览器于是把每一次 HTTP 4xx（最典型的就是 `/favicon.ico` 404）**上报到那个跨站域名**。
  实测一次首屏就发出 7 个请求 —— 这是全站唯一的跨站请求，广告拦截器报的「1 个追踪器」就是它。

三处改动彻底消除它：

1. `public/index.html` 加了内联 SVG favicon（data URI），不再有 `/favicon.ico` 404，
   也就没有了触发上报的错误响应。
2. `public/_headers` 里写了 `Nel: {"report_to":"cf-nel","max_age":0}`，
   `max_age=0` 等于让浏览器立刻丢弃这条 NEL 策略（实测能顶掉 Cloudflare 自动加的那条）。
3. 同时补上 CSP / nosniff / referrer-policy / permissions-policy 等头。

> **注意**：静态资源不经过 Worker（`run_worker_first` 只配了 `/api/*`），
> 所以 HTML/CSS/JS 的响应头必须写在 `public/_headers` 里，写在 Worker 代码里对它们无效。
> `/api/*` 的头则由 `src/index.js` 末尾的 `harden()` 统一附加。

复测结果：全新浏览器环境下，整页请求只剩 6 个，全部指向本站域名，跨站请求 0 个。

## 图片为什么会被压扁（已修）

正方形图片在列表里变成扁长方形，根因不是 CSS 没写 `max-width`，而是**列表的文本预览容器**：

`.thread p` 用了 `display:-webkit-box` + `-webkit-line-clamp:2`（只显示两行）。这个容器是**纵向的
旧版 flex**，图片作为其中的 flex item 默认 `flex-shrink:1`，容器高度只有两行 ——
于是图片被纵向压缩，宽度却不受影响，正方形就被压成了扁的。详情页因为 `.postBody` 不是 flex，
反而不受影响。

修法三条：

1. 列表预览里**不再把大图塞进那段被截断的文字**，改成文字下方一排固定尺寸的缩略图
   （`object-fit:cover` 裁切，但不拉伸），最多 4 张。
2. 详情页图片补上内联 `aspect-ratio`，任何一边被约束时浏览器都能按原比例反推另一边；
   CSS 再加 `object-fit:contain` 兜底。
3. 加载骨架图的 `min-height:110px` 改成只在「不知道图片尺寸」时生效
   （`img.att.loading:not([width])`）—— 已知尺寸时再叠固定高度，会把小图压变形。

## 关于两步验证（2FA）
- 基于 TOTP（RFC 6238，30 秒窗口，6 位码），兼容主流认证器应用。
- 开启后登录需两步：密码 → 认证器验证码。验证码前后各容差 1 个时间窗口，缓解设备时间偏差。
- **二维码由本地脚本绘制**（`/vendor/qrcode.min.js`，已随仓库提供）。
  早期版本从 jsdelivr/unpkg 加载，属于跨站请求，会被广告拦截器按「第三方追踪器」误拦；
  改为同源加载后不再触发拦截，内网与离线环境也能正常出图。
  即便脚本加载失败，仍可复制密钥在认证器中手动添加。
- 已开启 2FA 的账号，在修改密码、改用户名、注销时都需要额外输入一次验证码。
- 管理员账号不允许注销自己的账户。
- 用户丢失认证器时，可由管理员在管理中心关闭其 2FA（管理员自己的 2FA 不能被他人关闭）。

## 讨论板块

| 动作 | 游客 | 普通用户 | 子管理员 | 管理员 |
|---|---|---|---|---|
| 浏览板块 / 按板块筛选 | ✅ | ✅ | ✅ | ✅ |
| 创建板块 | ❌ | ✅ | ✅ | ✅ |
| 在板块里发帖 | ❌ | ✅ | ✅ | ✅ |
| 把主题挪到别的板块 | ❌ | ❌ | ✅ | ✅ |
| 删除板块 | ❌ | ❌ | ❌ | ✅ |

设计取舍：

- **创建开放、删除收紧**。板块是公共货架，人人都能添一格；但删除会波及里面所有人的帖子，
  所以只交给管理员 —— 否则等于给了随便一个人「清空某个话题」的权力。
- **删除板块不会删掉帖子**。里面的主题只是失去归属、回到「未分类」，一条都不少。
- **板块入口收在左上角菜单里**。横排一排胶囊在板块多了以后会换两三行，把首屏撑得很长；
  抽屉里按行排反而更适合长短不一的中文板块名（名字吃满宽度、超长省略号、计数右对齐）。
  代价是「当前筛的是哪个板块」不再一眼可见 —— 所以列表区必须保留那颗「板块 ▾」按钮，
  它就是为补这一点存在的，别顺手删掉。
- **移动主题是可逆的轻操作**（只改归属，不动内容也不碰作者），因此和置顶/锁定一样
  归入子管理员的内容治理白名单 `MOD_ACTIONS`。
- 发帖时填了不存在的 `boardId` 不会报错，会静默落到「未分类」—— 宁可少一个分类，也不要让帖子发不出去。

### 用真实数据体检（重要）
`tests/snapshot.cjs` 默认用一组**很乖的假数据**：清一色中文、没有长网址、没有代码块 ——
结果真机上「一条含 58 字符网址的帖子」就把整页撑到屏幕外，而快照一直是全绿的。

所以快照支持吃**线上真实数据**：把线上接口拉下来的 JSON 放在项目根目录再跑即可
（这些文件都在 `.gitignore` 里，不会误提交）：

```bash
curl -s https://你的域名/api/threads?limit=20 -o .live-threads.json
curl -s https://你的域名/api/boards        -o .live-boards.json
curl -s https://你的域名/api/threads/4     -o .live-t4.json      # 挑一条有回复的
node tests/snapshot.cjs                                    # 会打印 ⚑ 改用真数据渲染
node tests/viewport-check.cjs                              # 7 种比例 × 真数据
```

同时假数据里也**常驻一条「极端内容」**（标题与正文都塞了超长网址 + 一串没空格的英文），
即便没有线上数据，这条 bug 也不会再悄悄回来。

### 跨引擎 / 跨设备的底线
按 **Safari 15.4 / Firefox 98 / Chromium 100**（`<dialog>` 的分水岭）设计：
`color-mix()`、`popover`、`dvh`、`accent-color` 这些新特性都写了纯色 / 纯单位的退路
（由 `compat-check` 盯着），不支持时是「少一点效果」而不是「打不开」。
触屏上所有 `:hover` 位移都会被复位（iOS 会把 `:hover` 粘到下一次点击，卡片会一直"抬着"），
但 `:active` 的按下反馈会还回去。
改 UI 后跑一次就能同时拿到数字和截图（截图落在 `tests/fixtures/shot-*.png`）：

```bash
npm test        # 全部（含配色审计与布局检查）
npm run test:ui # 配色审计 + 布局截图 + 真实渲染快照 + 抽屉交互
npm run test:shot -- --view=admin   # 只重出某一个视图的快照
npm run test:nav                    # 只跑导航抽屉的交互检查
```

## UI 约定（改样式前先看）

`public/style.css` 按功能分区（设计令牌 → 配色方案 → 基础布局 → 通用组件 → 业务区块 →
弹窗浮层 → Markdown → 响应式），改之前先扫一眼文件头那段说明。

- **别写魔数**。间距用 `--sp-*`、圆角用 `--r-*`、控件高度只有 `--h-sm/--h-md/--h-lg`
  三档、字号用 `--fs-*`。「UI 风格大小不统一」就是这么来的 —— 每处都手写一个 px，
  迟早会出现 9px 和 10px 混着用。
- **别硬编码颜色**。中性色走 `--text/--muted/--line/--surface-*`，强调色走
  `--accent/--accent2/--accent-soft`（由 `--p-*` 提供），实心按钮走
  `--btn-bg/--btn-fg`。深色模式下 `--btn-bg` 会整个反过来 ——
  写成 `background:var(--text);color:#fff` 的话，深色下就是浅底白字，整颗按钮消失。
- **三个反复踩的 CSS 坑**（都写在注释里了）：
  ① `<button>` 不继承 `color`，每个按钮类都得显式写；
  ② 同特异性时后写的赢 —— `.mini` 会顶掉 `.primary` 的底色，组合态（`.mini.primary`）
     必须显式写全；
  ③ 中文没有词边界，flex item 的 min-content 只有一个汉字宽 ⇒ 按钮要
     `white-space:nowrap;flex:0 0 auto`，收缩的活交给文字那一栏。
- **`.danger` 既是按钮类也用在卡片上**（`class="setCard danger"`），
  所以按钮规则一律钉在 `button.danger` 上，否则整张卡片会被当成按钮排版。
- **管理中心的行**是 grid（`minmax(0,1fr) auto`）：左边永远 1fr、名字长了给省略号，
  右边按钮组 `flex:0 0 auto` 且右对齐。这样「不同用户名挤占不同空间」才不会复发；
  按钮组只有真的放不下时才整体换行。
- **提示条（toast）必须挂 `popover`**。`<dialog>` 打开时它和 `::backdrop` 整个进
  top layer，那里 z-index 完全无效 —— 普通定位的 toast 会被弹窗盖住，
  看起来就是「错误提示不在同一个图层」。
- 手机断点只有 `900 / 720 / 560 / 380` 四档，全在文件末尾，卡片宽度相关的判断
  尽量交给容器自身而不是视口。
